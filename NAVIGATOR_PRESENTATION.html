Your full EVOLV platform. All 16 pages — Ingest, Generate Requirements, Risk Assessment, Validation Factory, Sentinel, Developer Console, Project Navigator, and more.

The enterprise-grade Project Navigator. A standalone, production-quality UI for the project/release/folder hierarchy — built the way enterprise software is built.

  • Written in JavaScript — runs in browser natively
  • Cmd+K search, hover popovers, live animations

localhost:3000

The relationship: Page 16 in Streamlit is a basic version of what we just built in React. Eventually the React app talks to your FastAPI backend (port 8000) and replaces Streamlit as the primary UI. Streamlit stays for internal use and prototyping. React is what investors and CTOs see.

Feature 4 — FDA AI Guidance 2026

Every AI-generated artefact carries a pulsing 🤖 badge until a qualified human approves it. This is not cosmetic — it satisfies the FDA's January 2026 AI Guidance requirement for human oversight of AI-assisted decisions in regulated contexts.

→ Hover any item in the tree → Approve button appears → click it → badge clears → status updates

What the FDA regulation says:

FDA Guidance — AI/ML in Regulated Software (Jan 2026)
"Manufacturers using AI/ML tools in the development or validation process shall maintain human oversight mechanisms that allow qualified persons to review, approve, or reject AI-generated outputs before they are used as evidence in a validated system."
What this means in practice:
  • → EVOLV generates a URS from plain English. Fast. But…
  • → That URS cannot be used as GxP evidence until a person approves it
  • → The 🤖 badge is the visual signal. The approval click is the audit event
  • → After approval: humanApproved = true, badge gone, audit trail logged

⚠️ Risk Matrix heat:80
🧪 Test Scripts heat:75 🔴 HOT
🔗 Traceability heat:15
📄 VSR heat:10

How heat scores are calculated:

Heat Score 75–100 → Deep Red

Items with failed tests, open issues, or defects with no resolution. URS-008 (alert latency breach) and URS-011 (CoC bypass) drive the URS and Test Script folders into the red.

Heat Score 41–75 → Orange

Items in review, AI-generated but not yet human-approved, or requirements linked to high-risk items but not yet tested.

Heat Score 0–40 → Default / Green

Fully approved, human-reviewed items with passing tests and no open issues. These areas are stable and audit-ready.

Real-world use case: A CSV Manager walks into a pre-inspection meeting. They toggle the heatmap. In 3 seconds they see that the URS and Test Scripts folders in v1.1 are red, and VSR is green. They know exactly where to focus the team before the auditor arrives. This used to take a two-hour status meeting.

The logic behind each state:

// Computed per item in TreeNode.jsx

const hasIssue =
  node.status === 'open_issue'
  || node.status === 'failed'

const isValid =
  node.status === 'approved'
  && node.humanApproved === true

// CSS classes applied
hasIssue → 'glow-red' (CSS animation)
isValid → 'glow-green' (static glow)

Why this matters for audits: When an FDA inspector walks through your system, they see at a glance which items are clean and which have issues. You don't have to explain "yes that's a known issue we're tracking in Jira." The system surfaces it proactively — and it points to the specific incident ticket.
